# P3-08 i18n / Arabic RTL

## Supported locales

| Locale | Direction | UI |
|---|---|---|
| `zh` | LTR | default bilingual Chinese/English shell |
| `en` | LTR | English labels and status copy |
| `ar` | **RTL** | Arabic navigation, customer consent, onboarding and queue |

The shared helper is `src/i18n.js` (`normalizeLocale`, `isRtl`, `t`). It is unit-tested in `test/i18n.test.js`.

Server-side language detection already recognizes Arabic (`\u0600-\u06FF`) in `detectLanguage`; Arabic customer messages return `lang: "ar"` to the public API.

## Browser behavior

- Default: Chinese/bilingual shell, `dir="ltr"`.
- Explicit locale: `/chat.html?...&lang=ar`, `/onboarding.html?lang=ar`, `/queue.html?lang=ar`.
- A compact `中 / EN / ع` language switch is injected into the page header.
- The choice is stored in `localStorage` (`relaydesk_locale`) and reflected in the URL on the next navigation.
- `html[dir="rtl"]` mirrors layout, message alignment, table text, and the composer.
- All switches are same-origin; AC-05 remains green.

## Translation coverage

Major customer and merchant surfaces are translated:

- chat privacy title/body/consent, placeholder, send/voice/upload, hint, footer, welcome;
- onboarding subtitle, heading, lede, auth/site/knowledge/embed labels and actions, step labels;
- queue heading, subtitle, refresh, empty state, table headers, action button, footnote.

Dynamic server data (store name, product/order content, model reply, escalation message) remains in the customer's/merchant's content language. A full production translation service is a follow-up; this is the P3-08 outbound baseline.
